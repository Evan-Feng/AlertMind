# ADR-009: 相似度阈值 0.85 的实证依据

## 背景

阶段 3 聚合器基于 `BAAI/bge-small-zh-v1.5` embedding + cosine similarity 判断
alerts 是否归属同一 incident。需要一个相似度阈值作为「归属 vs 新建」的分界线。

## 决策

默认阈值设为 **0.85**（环境变量 `AGGREGATION_SIMILARITY_THRESHOLD` 可调）。

## 实证过程

### 校准方法

手工构造 15 对中文运维告警，每组 5 对，分为 3 类：

- **same**：明显相同事件的两条告警（如同一 alertname 不同 instance）
- **unrelated**：明显无关的两类告警（如 HighCPU vs DiskFull）
- **ambiguous**：模糊边界（如同 alertname 不同 service / 不同挂载点的 DiskFull）

校准 fixture：`backend/tests/fixtures/similarity_calibration.json`
校准脚本：`scripts/calibrate_similarity.py`

### 实测数据（2026-04-20）

| 分组 | 样本数 | 均值 | min | max |
|------|--------|------|-----|-----|
| same | 5 | 0.9876 | 0.9692 | 1.0000 |
| unrelated | 5 | 0.7091 | 0.6422 | 0.7862 |
| ambiguous | 5 | 0.8991 | 0.7953 | 0.9905 |

### 关键观察

- same 下界（0.9692）与 unrelated 上界（0.7862）之间有 **0.18 的安全 gap**
- 0.85 阈值处于此 gap 中间，能完美切分 same / unrelated（gap 内无样本）
- ambiguous 内部分化合理：3 对 > 0.85（被聚合）、2 对 < 0.85（保持分开）

## 已知局限

- **跨 service 同类告警**（如 `HighRequestLatency on service-A` vs `service-B`）
  在 0.85 阈值下可能被过度聚合（实测样本中相似度 0.9905）
- 这不是阈值本身的问题，是文本拼接策略对 `service` / `job` 标签权重不足
- 工作绕过：
  - 调高阈值到 0.95
  - 给 alert annotations 加 `service` 字段让文本更可区分
  - v0.2 引入 `AGGREGATION_GROUP_BY` 硬分区机制

## 调整规则

如需重新调整阈值：

1. 重跑校准脚本：`cd backend && uv run python ../scripts/calibrate_similarity.py`
2. 观察 same / unrelated 分布是否发生变化（如换了 embedding 模型）
3. 调整 `.env` 中的 `AGGREGATION_SIMILARITY_THRESHOLD`
4. **必须同步更新本文档的实测数据表与日期**
5. 重跑 E2E 验收脚本 `scripts/e2e_phase3.sh` 确认聚合行为符合预期
